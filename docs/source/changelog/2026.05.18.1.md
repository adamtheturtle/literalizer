# 2026.05.18.1

- `~literalizer.languages.rust.Rust` now exposes a non-empty `Modifiers` enum with a single `MUT` member.
  Passing `NewVariable(name=..., modifiers={Rust.Modifiers.MUT})` (or the same via `~literalizer.literalize_call`) renders a mutable binding (`let mut name = ...;`) instead of the immutable default (`let name = ...;`), so a value constructed and bound through the variable form can then be mutated through that binding.
  The modifier applies to the default `LET` declaration style; other declaration styles ignore it.
- Added two metadata properties to the `~literalizer.Language` protocol: `supports_multi_param_call_wrapper_stub` (whether the language can declare and positionally invoke a wrapper stub that receives the call's result alongside other positional arguments) and `supports_dict_literal_as_free_expression` (whether a map literal can appear as a free-standing expression rather than only on the right-hand side of a typed assignment).
  These flags describe generated-stub and expression capabilities; `~literalizer.literalize_call` does not inspect them.
