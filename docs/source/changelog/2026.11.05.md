# 2026.11.05 (2026-11-05)

## Changes

- Add `ObjectiveC.dict_entry_styles.SPACED` to emit spaces on both sides of dictionary colons, including ordered maps and nested collections.
  Existing output remains unchanged by default.
  ([#6781](https://github.com/adamtheturtle/literalizer/issues/6781))
- Add independent Objective-C native argument layout, selector alignment, continuation indentation, collection layout, and line-width options.
  Native invocation APIs accept caller-owned initial columns and account for binding prefixes while rendering the typed invocation tree directly.
  Existing inline output remains the default.
  ([#6782](https://github.com/adamtheturtle/literalizer/issues/6782))
- Add independent Objective-C `indent_file_body` and `expand_call_stubs` options for directly emitted wrapper scopes and helper statements.
  Both preserve existing output by default and honor the configured indentation string.
  ([#6783](https://github.com/adamtheturtle/literalizer/issues/6783))
- Emit Python typing imports only when native record annotations require them.
- Match Kotlin record tuple field types to the emitted widened integer literals.
- Match Rust record tuple fields to integer literals widened beyond 64 bits.
- Reject empty byte strings in plain COBOL text storage instead of emitting an invalid zero-length literal.
- Remove leading zero padding from PureScript floating-point exponents.
- Retain Swift type context and validate Nim value types for ordered maps containing refined native records.
- Retain native payload headers for C++14 record map fallback carriers.
- Reuse runtime-checked callable implementations when constructing shared and C++ type resolvers, avoiding repeated type-checking wrapper generation during rendering.
- Tag empty YAML text literals explicitly so strict flow-collection indentation checks accept empty byte encodings while preserving scalar collision checks.
